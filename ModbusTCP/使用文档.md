# Modbus TCP 网关使用文档

## 1. 目标链路

本工程实现下面这条控制链路：

```text
电脑 MyPC
  Modbus TCP 主站
        |
        | 以太网 / Wi-Fi
        v
LPB3568
  Modbus TCP 从站/服务器
  Modbus RTU 主站
        |
        | RS485
        v
STM32
  已有 Modbus RTU 从站
```

最终效果：电脑通过 Modbus TCP 访问 LPB3568，LPB3568 再通过你已有的 Modbus RTU 代码访问 STM32，从而控制 STM32 的 LED、PWM，并读取 heartbeat。

## 2. 目录说明

当前 `ModbusTCP` 下主要使用两个目录：

```text
ModbusTCP/
  MyPC/         电脑端程序，Modbus TCP 主站
  LPB3568_TCP/  LPB3568 端程序，Modbus TCP 到 Modbus RTU 网关
```

寄存器地址沿用你原来的 STM32 RTU 工程：

| 地址 | 含义 | 取值 |
| --- | --- | --- |
| 0 | LED 模式 | 0 关，1 红，2 绿，3 蓝，4 黄，5 紫，6 青，7 白 |
| 1 | PWM 占空比 | 0..1000 |
| 2 | heartbeat | STM32 每秒递增 |

## 3. 运行前检查

先确认硬件和网络：

1. STM32 和 LPB3568 的 RS485 已接好，A/B 不要接反。
2. STM32 的 Modbus RTU 从站程序已经烧录并能正常运行。
3. STM32 的从站 ID 默认按 `1` 使用，波特率默认按 `9600` 使用。
4. 电脑和 LPB3568 在同一个局域网，电脑能 ping 通 LPB3568。
5. 确认 LPB3568 上连接 RS485 的串口名，例如 `/dev/ttyS7`。

在 LPB3568 上查看 IP：

```sh
ip addr
```

在电脑上测试网络：

```sh
ping <LPB3568-IP>
```

## 4. 编译 LPB3568 网关程序

把 `ModbusTCP/LPB3568_TCP` 目录放到 LPB3568 上，然后执行：

```sh
cd ModbusTCP/LPB3568_TCP
make
```

如果是在电脑上交叉编译：

```sh
cd ModbusTCP/LPB3568_TCP
make CC=aarch64-linux-gnu-gcc
```

编译成功后会生成：

```text
lpb3568_modbus_tcp_gateway
```

## 5. 运行 LPB3568 网关程序

推荐先用 1502 端口测试，因为 502 端口通常需要 root 权限。

```sh
cd ModbusTCP/LPB3568_TCP
./lpb3568_modbus_tcp_gateway /dev/ttyS7 9600 1502
```

参数含义：

| 参数 | 含义 |
| --- | --- |
| `/dev/ttyS7` | LPB3568 连接 STM32/RS485 的串口 |
| `9600` | RTU 波特率，要和 STM32 一致 |
| `1502` | Modbus TCP 监听端口 |

如果你要使用标准 Modbus TCP 端口 502：

```sh
sudo ./lpb3568_modbus_tcp_gateway /dev/ttyS7 9600 502
```

正常启动后会看到类似输出：

```text
LPB3568 Modbus TCP to RTU gateway
  TCP listen port : 1502
  RTU serial dev  : /dev/ttyS7
  RTU baudrate    : 9600
  TCP unit id maps to STM32 RTU slave id
```

## 6. 编译电脑端 MyPC 程序

### Windows + MinGW/MSYS2

进入目录：

```sh
cd ModbusTCP/MyPC
mingw32-make
```

如果没有 `mingw32-make`，也可以直接编译：

```sh
gcc -O2 -Wall -Wextra -std=c99 -Iinclude src/main.c src/modbus_tcp_master.c src/tcp_client.c -lws2_32 -o mypc_modbus_tcp_master.exe
```

### Linux

```sh
cd ModbusTCP/MyPC
make
```

## 7. 运行电脑端程序

假设：

- LPB3568 的 IP 是 `192.168.1.30`
- LPB3568 网关监听端口是 `1502`
- STM32 RTU 从站 ID 是 `1`

Windows：

```sh
cd ModbusTCP/MyPC
mypc_modbus_tcp_master.exe 192.168.1.30 1502 1
```

Linux：

```sh
cd ModbusTCP/MyPC
./mypc_modbus_tcp_master 192.168.1.30 1502 1
```

最后的 `1` 很重要：它会作为 Modbus TCP 的 `unit id` 发给 LPB3568，LPB3568 再把它当作 STM32 的 RTU 从站 ID。

## 8. 菜单操作顺序

电脑端启动后会出现菜单：

```text
1. Select STM32 slave id
2. Set STM32 LED color
3. Set STM32 PWM duty
4. Collect STM32 LED/PWM/heartbeat
5. Read one holding register
6. Write one holding register
q. Quit
```

建议第一次按这个顺序测试：

1. 选择 `4`，读取 LED/PWM/heartbeat，确认链路能读。
2. 选择 `2`，设置 LED 颜色，例如输入 `1` 设置红色。
3. 选择 `3`，设置 PWM，例如输入 `500`。
4. 再选择 `4`，确认 LED/PWM/heartbeat 读回值正确。

## 9. 调试模式

如果通信不正常，可以打开调试帧打印。

LPB3568：

```sh
MODBUS_DEBUG=1 ./lpb3568_modbus_tcp_gateway /dev/ttyS7 9600 1502
```

MyPC Linux/MSYS2：

```sh
MODBUS_DEBUG=1 ./mypc_modbus_tcp_master 192.168.1.30 1502 1
```

Windows cmd：

```bat
set MODBUS_DEBUG=1
mypc_modbus_tcp_master.exe 192.168.1.30 1502 1
```

Windows PowerShell：

```powershell
$env:MODBUS_DEBUG="1"
.\mypc_modbus_tcp_master.exe 192.168.1.30 1502 1
```

## 10. 常见问题

### 电脑连不上 LPB3568

先检查：

```sh
ping <LPB3568-IP>
```

再确认 LPB3568 程序是否正在运行，端口是否一致。比如 LPB3568 开的是 `1502`，电脑端也必须填 `1502`。

### 502 端口启动失败

Linux 下 502 是低端口，通常需要 root 权限：

```sh
sudo ./lpb3568_modbus_tcp_gateway /dev/ttyS7 9600 502
```

调试阶段更推荐用 1502：

```sh
./lpb3568_modbus_tcp_gateway /dev/ttyS7 9600 1502
```

### TCP 能连上，但读写失败

重点检查 RTU 侧：

1. 串口名是否正确，例如 `/dev/ttyS7`。
2. 波特率是否和 STM32 一致，例如 `9600`。
3. STM32 slave id 是否和电脑端最后一个参数一致。
4. RS485 A/B 是否接反。
5. STM32 程序是否已经运行，heartbeat 是否在递增。

### 返回负数错误码

常见含义：

| 错误码 | 大致含义 |
| --- | --- |
| `-1` | Modbus 异常码 1，非法功能 |
| `-2` | Modbus 异常码 2，非法地址 |
| `-3` | Modbus 异常码 3，非法数据值 |
| `-11` | 网关访问 STM32 失败，常见于 RTU 超时、接线、波特率、slave id 不一致 |

### LED/PWM 写入成功但没有变化

电脑端写 LED/PWM 后会自动读回确认。如果读回值正确但硬件没变化，问题大概率在 STM32 的寄存器应用逻辑或 LED/PWM 外设初始化；如果读回值不正确，优先查 RTU 通信链路。
